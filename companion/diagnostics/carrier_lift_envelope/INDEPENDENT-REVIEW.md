# Independent stationary lift/lower envelope review

Verdict: **APPROVED for the declared stationary articulation envelope**. Exact identities are in `review-source-hashes.json`. This is the union of the approximate rig capsules during the existing carrier's lift/lower IK. It is not a rigid-pose certificate, full avatar mesh enclosure, continuous desktop sweep implementation review, or Windows acceptance result.

The analytic construction divides lift [0,1] into 16 intervals. For each midpoint it reconstructs the actual fixed-hip two-bone solution, including clamped reach. A derivative bound covers target direction, normalized knee pole, axial knee coordinate and perpendicular knee height throughout the interval. Multiplying the speed bounds by interval half-width encloses endpoint displacement; expanding each capsule by the maximum endpoint displacement therefore encloses its whole segment. Foot endpoints translate with the solved ankle while the preserved global foot basis remains fixed. Non-leg capsules remain at the frozen body pose. The skeleton-to-avatar radius multiplier is conservative under scale and shear.

The clamped distance is Lipschitz with the target's vertical speed. The code bounds the potentially singular direction, pole normalization and perpendicular knee-height denominators over each interval and rejects intervals crossing the solver's fallback/singular region. This is a failure-closed supported-path contract rather than an approximation across a different IK branch.

Three review corrections are included. First, target clearance is captured from the exact runtime REST-based leg length; it is not recomputed from posed segment lengths. Second, changing floor clearance or floor height invalidates the carrier and both its rigid and lift proofs, avoiding a stale baseline envelope. Third, every returned capsule receives an explicit scale-aware numeric guard equal to 1e-5 times the maximum posed leg length. The guard is reported separately and covers the measured float solver discrepancy instead of depending on a permissive acceptance tolerance.

Independent evidence:

- `review-runtime.json/log`: five real rigs, 483 forward/reverse phases each, actual authored entry and existing LegIK. All report zero positive endpoint/radius overflow and exact zero skeleton pose mutation. Query calls preserve clocks and diagnostic dictionaries. Initial inactive/pre-first-process queries return no envelope; repeated queries return equal fresh data and caller mutation does not poison later queries. Public floor changes immediately invalidate both proof APIs and the active helper clears on its next application. Maximum local query cost is 794 microseconds. Returned envelopes contain 105 capsules, with analytic margins 0.926–3.323 mm plus the numeric guard. Report values were independently asserted to have exactly zero overflow, beyond the fixture's original 1-micrometre failure threshold.
- `review-derivatives.json/log`: an independent constructed three-bone skeleton runs actual LegIK for 570 accepted intervals with 17 samples each, varying unequal segment lengths, upward/downward and near-pole targets, and reach clamps. Six intervals reject. Separate zero-direction and fallback-pole cases reject. The largest raw numerical excess over the analytic margin is 0.937 micrometres; all samples fit within the explicit length-scaled numeric guard.

The source scripts for both independent fixtures are under `diagnostics/authored_foot_contacts/review_lift_*.gd` and included in the identity manifest. The runtime path restores the captured body and applies frozen-phase floor contact before caching the prelift reference; it captures no already-lifted endpoint. The envelope query only reads that cache and current avatar transform and performs no temporary skeleton solve.

This review covers supported finite, fixed-floor, fixed-source carrier paths. It retains the body-capsule exclusions for hands, garments, hair and accessories, and does not certify arbitrary externally mutated skeleton transforms, arbitrary rigs, all singular configurations, host placement or rendered timing. No production source or Windows process was changed by the reviewer.
