# Render padding review and outline correction

Verdict: **APPROVED for the bounded render-padding integration after the outline correction**. Main's concurrent authored-seat, movement and floor changes are outside this review.

Main separates the 680×760 reference film from the 1160×1120 transparent render canvas. Orthographic pixel scale uses the reference model height while actual viewport height determines orthographic camera size. Perspective focal scale, canonical camera film and world origin still use the original reference size. The default foot now centers horizontally in the larger render area; the canonical perspective camera retains its separate reference foot, so this redistribution does not alter stored furniture coordinates. Hit/fit bounds use render dimensions, while the subtitle follows projected pet center. The independent actual-main three-rig test passed 63 checks, including pixel scale in both modes and fixed-world projection under simulated OS window movement. The parent separately reports 623 native self-tests; this reviewer did not rerun that complete suite.

One regression was found: leaving the old screen-outline shader unmodified would increase vertical outline width by 1120/760 (47.4%), and changing canvas aspect also changes its normalized outline direction. At the parent's request, this reviewer implemented a narrowly scoped shader/helper correction. The main hook remains parent-owned.

The new optional legacy reference-size uniform first rescales the projection-normal XY components by actual viewport size / reference size before the existing normalization, reconstructing the original symmetric orthographic projection ratio. Multiplying final legacy clip-width by reference height / actual height then preserves original pixel extrusion. The perspective branch and original view-space Z mouth fix remain unchanged. The helper rejects non-finite/non-positive reference sizes and resets the unused uniform during mode changes. Main supplies the original reference size only in orthographic mode.

A separate reviewer, Astra Face, independently approved this implementation and compared 4,000 normal/viewport combinations to original reference extrusion (maximum reported error 1.27e-13 pixels). Installation patch reverse dry-run succeeded against the installed shader.

A real fixed-pose Cheval render was captured locally using Linux llvmpipe OpenGL Compatibility. Comparing a 680×760 baseline to the corresponding rectangle inside a 1160×1120 canvas: pixels differing by more than 0.02 RGBA fell from 1,108 without compensation to 80 with correction; mean visible-pixel channel error fell from 0.00192056 to 0.000116281. This is improvement evidence, not exact image identity. All three images and the report remain in `logs/outline-padding-review`; summary is copied to `outline-padding-render.json`. The actual corrected avatar image was inspected.

This review does not establish Windows D3D12 compositing, maximum-motion containment, unchanged saved desktop placement, or rendering performance. The parent owns the larger-canvas native checkpoint and the previously failing diagonal overhead-stretch containment case. Pixel padding can increase render workload; no timing or GPU-memory claim is made.
