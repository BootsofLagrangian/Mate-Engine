# Audio-input-only Omni → existing character TTS experiment

This isolated experiment replaces STT + text-only LM with a Qwen2.5-Omni Thinker that receives waveform features directly. Character speech still comes from the existing local UmaDiffusion GPT-SoVITS service. No Omni Talker or Token2Wav is instantiated. The running production UI/backend is not switched by these scripts.

## Reproduce

From the Mate-Engine repository, with the existing companion server running:

```bash
./companion/experiments/omni/setup.sh
../.venv-omni/bin/python companion/experiments/omni/make_inputs.py
../.venv-omni/bin/python companion/experiments/omni/baseline.py
../.venv-omni/bin/python companion/experiments/omni/run_probe.py
```

For your own recording (up to 30 seconds):

```bash
../.venv-omni/bin/python companion/experiments/omni/infer_wav.py /path/to/korean.wav
```

The CLI prints dialogue/action events and the resulting local WAV path. It does not capture the physical microphone or automatically play sound. The existing TTS endpoint must be running at `127.0.0.1:9880`; the control ASR tests also need the companion endpoint at `127.0.0.1:8765`.

## What the test does

- Uses original Qwen2.5-Omni-3B revision `f75b40e3da2003cdd6e1829b1f420ca70797c34e`, BF16, SDPA, all parameters on CUDA.
- Makes a Thinker-only index referencing unchanged tensors in upstream shards 1/2. The Talker/Token2Wav-only third shard is unnecessary. The model still includes its visual encoder, although no images enter this test.
- Passes audio samples + fixed character instructions to the model. **Fixture transcripts, expected meanings and Whisper results never enter Omni's inputs.** The named WhisperFeatureExtractor is a mel frontend, not a speech-to-text model invocation.
- Reuses the existing clause splitter and GPT-SoVITS output path, including supplied reference voice and original weights. Hashes in the report identify the local configured checkpoint files; the benchmark uses the existing supervised TTS process.
- Uses five synthetic Korean INPUT files generated by `facebook/mms-tts-kor`, seed 42. This fixture generator is not used for character OUTPUT. These are not recordings of the user and do not establish robustness to natural microphone audio.
- Checks the inputs separately with Whisper and checks generated Japanese speech by ASR. ASR agreement is not human listening or voice-similarity evaluation.
- Stops non-Japanese-script text before it reaches TTS. Kanji/kana script checks alone do not prove Japanese semantic correctness.

Intended meanings, fixed before model runs: greeting/day question; tea instead of coffee; exam passed/happy; exam failed/sad; slow right-hand wave. Assess reply meaning separately from JSON validity and audible output. The existing motion interface can only select a gesture name, not encode speed or handedness.

## Timing and memory scope

`logs/omni/results.json` records first PCM arrival measured from starting the offline audio request, preprocessing, model completion and total synthesis time. Recording time and initial checkpoint loading are excluded. The first case is Omni-cold (newly loaded model), not necessarily TTS-cold; the final case repeats the first for a warm comparison.

`baseline.json` starts timing at audio upload to the existing STT endpoint and includes STT + the text-LM/TTS pipeline. There is no browser playback measurement in this experiment. The systems differ in model, decoding constraints, context wrapping and cache handling, so their comparison is not an isolated causal measurement of the audio encoder alone.

CUDA allocated/reserved peaks are explicitly **Omni-process-only**, excluding separate TTS/STT processes and Windows/VRM rendering. The frontend caps padding at actual signal length plus an STFT window; valid features matched the default 300-second padded frontend exactly on the checked tea-input fixture. That one comparison is not universal numerical equivalence across all recordings.

Artifacts are under ignored `companion/logs/omni/`, inputs under `logs/omni-inputs/`, audio outputs under `output/`. See `RESULTS.md` once the GPU run is assessed.
